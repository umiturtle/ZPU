# ZAPP ロードマップ（詳細版）

## プロジェクトビジョン

Zigのエコシステムに**現代的で高速なUIフレームワーク**をもたらすことを目指します。

### 核となる価値
1. **パフォーマンス第一** - 120FPS、可変リフレッシュレート、ゼロ GC
2. **開発者体験（DX）** - ホットリロード、型安全、直感的API
3. **国際化（i18n）** - 日本語を含む多言語テキスト入力
4. **カスタマイズ性** - テーマ、レイアウト、動作をユーザーが制御
5. **プラットフォーム中立** - ネイティブとWebの両方をサポート
6. **アクセシブル** - 誰もが使えるUI

---

## 現在の課題

1. **文字レンダリング** - フォントデータが簡易的、文字が判読しにくい
2. **座標系の分離** - 実ピクセルと仮想ピクセルが混在
3. **テスト容易性** - レンダリングロジックとデータが密結合
4. **パフォーマンス** - 120FPS、可変リフレッシュレート未対応
5. **i18n** - 日本語入力未対応
6. **DX** - ホットリロード未対応
7. **Web連携** - ブラウザでの動作未検証
8. **カスタマイズ** - テーマ、スタイルの変更が困難

## リスクと対策

| リスク | 影響 | 対策 |
|-------|------|------|
| Zigコンパイラの不安定さ | 開発遅延 | 固定バージョン使用、CIで早期検出 |
| WASMの制約 | Web機能制限 | 段階的機能縮退、ブラウザAPI活用 |
| パフォーマンス目標未達 | コアバリュー喪失 | 早期ベンチマーク、ボトルネック特定 |
| 日本語入力の複雑さ | i18n遅延 | IME仕様の早期調査、段階的実装 |
| カスタマイズ性とパフォーマンスのトレードオフ | 両立困難 | 段階的実装、ベンチマークで検証 |
| コミュニティの成長遅延 | 採用遅れ | 積極的な情報発信、サンプル充実 |
| Linux/Waylandの断片化 | 動作環境の差異 | X11/Wayland両対応、CIで複数環境テスト |
| Webブラウザの差異 | 動作の一貫性 | 主要ブラウザでのテスト、ポリフィル活用 |
