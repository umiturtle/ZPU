# ZPU documentation

**A numerical computing library (`zpu`), a general purpose graphics library
(`zgf`) and a 2-D UI library (`zui`), all written in Zig.** No external dependencies, the build is a single
`zig build`, and the tests, benchmarks and this documentation are all Zig programs.

```sh
zig build test     # unit + numerical tests, leak checked
zig build check    # zig fmt --check plus the tests
zig build bench    # throughput measurements
zig build doc      # regenerate this HTML
```

## The whole picture in 30 seconds

* **`zpu`** — an N-dimensional `Tensor` and eager `ops`, reverse and forward mode
  automatic differentiation (`tape` + `autodiff`), the function transforms
  `grad` / `jvp` / `vmap` / `jit`, a recording `graph` with a replayable plan,
  a neural network layer (`nn`), optimisers (`optim`), random numbers (`rng`)
  and linear algebra (`linalg`).
* **`zgf`** — images and drawing. An image *is* a `zpu.Tensor`, so filters are
  ordinary tensor expressions and can be differentiated like anything else.
* **`zui`** — 2-D UI: an immediate-mode widget API, a retained display list and a
  minimal retained state (a hybrid, chosen from Zig's properties). An idle frame
  runs no body at all (~15 ns) and the display list rasterises into a `zgf` image,
  which is what makes a UI testable.
* **`zbackend`** — detection and dispatch for WebGPU / Metal / Vulkan / DirectX 12
  through `std.DynLib`, behind one `Kernel` / `Buffer` / `dispatch` interface,
  with the CPU backend always available as the fallback.

```zig
const zpu = @import("zpu");

try zpu.init(alloc, .{});
defer zpu.deinit();

const x = try zpu.Tensor.fromArray(f64, &.{ 1, 2, 3, 4 }, zpu.Shape.initComptime(&.{ 2, 2 }));

// eager results belong to the scope that produced them
var scope = try zpu.Scope.init(alloc);
defer scope.deinit();
const y = try zpu.tanh(try zpu.matmul(x, x));

// a transform hands ownership to the caller instead
const g = try zpu.grad(alloc, loss, null, &.{x}, &.{0});
defer alloc.free(g);
```

## About this documentation

* The source of truth is the repository: this page is `docs/en/index.md`, and the
  Japanese edition lives next to it in `docs/`. The HTML is generated by
  `docs/build_docs.zig` (`zig build doc`). No Python, no static site generator.
* Every API page is extracted from the `//!` and `///` comments in the sources, so
  the HTML cannot drift away from the code.
* The English pages are a translation of the Japanese originals, page for page:
  use the switcher in the header to compare them.
